# Gemini Web 2.0 — Termux / Android

رابط چت فارسی، راست‌چین و محلی برای Gemini؛ با Node.js و HTML/CSS/JavaScript خالص و بدون وابستگی npm.

## امکانات

- اتصال واقعی به Gemini REST API با `generateContent` و `streamGenerateContent` (SSE)
- توقف تولید با `AbortController` و حفظ متن دریافت‌شده
- نگهداری کلید API فقط در سرور و فایل `.env`
- تاریخچه محلی، ایجاد/بازکردن/جست‌وجو/تغییرنام/حذف گفتگو
- ویرایش پیام، تولید مجدد، خروجی Markdown و JSON
- تنظیم مدل، Temperature، حداکثر توکن و دستورالعمل سیستمی
- تم تاریک/روشن، رابط RTL و واکنش‌گرا
- پیوست حداکثر ۴ فایل در هر پیام، هر فایل حداکثر ۳ MiB:
  - تصویر: JPEG، PNG، WEBP، GIF (با inline data)
  - سند PDF (با inline data)
  - متن: TXT، Markdown، CSV، JSON (محتوا به‌صورت متن UTF-8 به Gemini داده می‌شود)
- جست‌وجوی وب اختیاری با Google Search grounding؛ با دکمه «وب» کنار کادر پیام فعال/غیرفعال می‌شود و لینک منابع برگشتی نمایش داده می‌شود
- رندر Markdown محدود و escape کردن HTML؛ کپی کد
- اعتبارسنجی درخواست‌ها، محدودیت اندازه، rate limit محلی، timeout و هدرهای امنیتی
- فقط bind روی `127.0.0.1` به‌صورت پیش‌فرض

## نیازمندی‌ها

- Termux و Node.js دارای `fetch` سراسری (Node.js 20+)
- اینترنت و کلید فعال Gemini API
- پروژه هیچ بسته npm یا افزونه native ندارد؛ سازگاری عملی به نسخه Node.js قابل نصب در مخزن Termux و معماری دستگاه وابسته است.

## نصب در Termux

```bash
pkg update
pkg install nodejs unzip nano -y
termux-setup-storage
```

فایل ZIP را در پوشه Download گوشی قرار بده. سپس:

```bash
cd ~/storage/downloads
cp gemini-web-2-termux-fixed.zip ~/
cd ~
unzip gemini-web-2-termux-fixed.zip
cd gemini-web-2-termux-fixed
cp .env.example .env
nano .env
```

مقدار `GEMINI_API_KEY` را با کلید واقعی خودت عوض کن. کلید را در `public/` یا پیام‌های چت قرار نده.

## اجرا

```bash
npm run check
npm start
```

در مرورگر گوشی باز کن:

`http://127.0.0.1:3000`

برای توقف سرور `Ctrl+C` را بزن.

## تست‌های پایه

در پوشه پروژه:

```bash
npm run check
curl http://127.0.0.1:3000/api/health
```

بررسی درخواست نامعتبر:

```bash
curl -i -X POST http://127.0.0.1:3000/api/chat \
  -H 'Content-Type: application/json' -d '{}'
```

اگر کلید تنظیم نشده باشد، health مقدار `configured:false` و درخواست چت پاسخ 503 با کد `MISSING_API_KEY` می‌دهد. برای تست انتهابه‌انتها، کلید معتبر و نام مدلی که حساب تو اجازه استفاده از آن را دارد لازم است.

## پیوست فایل

از دکمه `＋` کنار پیام استفاده کن. فایل‌های مجاز در این نسخه تصویر، PDF، TXT، MD، CSV و JSON هستند؛ سقف ۳ MiB برای هر فایل و ۴ فایل در هر پیام است. PDF و تصویر به‌صورت inline data به Gemini می‌روند. فایل‌های متنی UTF-8 در سمت سرور خوانده و به‌عنوان متن به prompt اضافه می‌شوند. فایل‌های Word، Excel، ZIP و ویدئو در این نسخه پشتیبانی نمی‌شوند.

## جست‌وجوی وب

دکمه «وب» کنار کادر پیام، Google Search grounding را برای درخواست بعدی روشن یا خاموش می‌کند. در حالت روشن، backend ابزار `google_search` را به درخواست Gemini اضافه می‌کند و اگر Gemini داده‌های grounding برگرداند، پیوندهای منبع زیر پاسخ نمایش داده می‌شوند. این قابلیت به مدل انتخابی، API version، دسترسی حساب و پشتیبانی Google از ابزار برای آن مدل وابسته است؛ اگر API خطا بدهد، پیام خطا نشان داده می‌شود و برنامه ادعا نمی‌کند که جست‌وجو انجام شده است.

## تنظیمات و محدودیت‌ها

- مدل اولیه `gemini-2.5-flash` است؛ این نام تضمین‌کننده دسترسی حساب نیست. مدل را از پنل تنظیمات تغییر بده.
- تاریخچه در localStorage مرورگر نگهداری می‌شود؛ پاک‌کردن داده‌های سایت ممکن است آن را حذف کند. محتوای فایل‌های پیوست‌شده به‌صورت کامل در تاریخچه ذخیره نمی‌شود؛ نام فایل‌ها و پیش‌نمایش تصاویر در صورت ذخیره شدن در مرورگر ممکن است باقی بماند.
- endpoint فهرست مدل‌های قابل دسترسی حساب ارائه نشده است.
- Rate limit درون‌حافظه‌ای و مناسب استفاده محلی است، نه میزبانی عمومی.
- برنامه را روی `0.0.0.0` منتشر نکن. برای دسترسی شبکه‌ای، احراز هویت و TLS لازم است.

## چک‌لیست وضعیت

| قابلیت | وضعیت |
|---|---|
| سرور و رابط localhost | پیاده‌سازی و تست پایه |
| Gemini generateContent / streaming | پیاده‌سازی؛ نیازمند کلید معتبر برای تست زنده |
| توقف تولید | پیاده‌سازی با AbortController |
| تاریخچه و مدیریت گفتگو | پیاده‌سازی |
| تنظیمات مدل و تولید | پیاده‌سازی و اعتبارسنجی سمت سرور |
| تصاویر | پیاده‌سازی؛ تحلیل وابسته به مدل چندرسانه‌ای |
| PDF | پیاده‌سازی با inline data؛ نیازمند تست زنده با مدل سازگار |
| TXT / MD / CSV / JSON | پیاده‌سازی؛ UTF-8 |
| Google Search grounding | پیاده‌سازی؛ نیازمند دسترسی مدل/API و تست زنده |
| DOCX / XLSX / ZIP / ویدئو | پشتیبانی نمی‌شود |
| فهرست زنده مدل‌های مجاز حساب | پشتیبانی نمی‌شود |
| احراز هویت برای شبکه عمومی | پشتیبانی نمی‌شود؛ عمداً localhost-only |
